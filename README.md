# 水文监测站网管理系统

面向水文监测站点运行、水位流量雨量数据采集、遥测设备维护与数据整编发布的水文站网管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydrology-monitor-station:entries` 这一项，或调用 `resetModule(模块)`。

## 水位审核链路

水位记录有专门的领域层 `frontend/src/data/water-level.ts`，水位详情、预警面板、数据整编列表三处
判定都来自它，口径一致：

- **数值化与缺测边界**：当前水位/警戒水位/保证水位/变幅统一解析为数值（米）。空、`—`、`缺测`
  等按**缺测**处理；有内容但解析不出、或超出物理合理区间按**采集异常**处理。两类都不计「正常」。
- **等级判定**：当前 ≥ 保证为「超保证」，≥ 警戒为「超警戒」；**警戒水位缺测时一律不判正常**
  （即使保证值可用且未超），显式显示「警戒缺测」并说明原因。
- **变幅勾稽**：变幅按同站相邻测次的当前水位之差重算，原值与重算值不符时标 `*` 并给出原值，
  保证当前水位、保证水位、变幅三者对得上。
- **审核状态机**：缺测/异常/阈值缺测的记录「确认通过」会被拦截；异常记录只能「重新校验」回待审核
  重走全部校验，根因未消除时重试失败并保留 `lastError`，不会残留为「已通过」；「中断审核」回待审核
  并记录中断原因。
- **幂等提交**：按「站点编号 + 观测时间」upsert，重复/并发提交只留一条有效记录（新值覆盖）。
- **并发审核**：每条记录带 `rev` 乐观锁，审核需携带取数时版本，过期写入被拒，只落一个审核结果。
- **复核链路**：localStorage 键 `hydrology-monitor-station:reviews`。水位审核入口与预警阈值配置
  入口（发布生效/调整阈值）都写入同一条复核记录，页面底部的「复核记录」面板统一呈现。
- **历史兼容**：旧的裸 entries 存储自动迁移到 `{ version: 2, entries }`，迁移只补 `rev`、合并新增
  种子记录，不翻转任何历史 `status/abnormal` 结论。

```bash

npm run test:domain
```
